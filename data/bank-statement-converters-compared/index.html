Why does the balance check matter?

Every converter reads a PDF and writes rows. The ways that goes wrong are quiet: a line on a page break is dropped, a deposit is read as a withdrawal, one digit is misread. The file still opens in Excel and looks fine. The only fast proof is arithmetic the bank already printed: opening balance + deposits − withdrawals = closing balance. Four of the nine tools say they run some form of that check; ZeraBooks runs it on every statement and will not hand you a file that silently doesn't tie.

How do you test any converter in two minutes?

  1. Check 1, the totals. Sum the extracted amounts, add the printed opening balance, and compare with the printed closing balance. The difference must be 0.00.
  2. Check 2, the running balance. If the statement prints a balance on each line, compare it with the running total of the extracted rows. The first line where they split is where the error is.

Worked example (fictional): a Bank of America business statement for September 2026 with 18 lines. Opening 26,718.44 + deposits 29,554.05 − withdrawals 26,456.01 = 29,816.48, the printed ending balance. A converter that drops the 1,240.00 equipment loan payment would end at 31,056.48, off by exactly that amount.

How do I check if a converted bank statement is correct?

Add the printed opening balance to the sum of the extracted transactions. The result must equal the printed closing balance. If a running balance column was extracted, it must match line by line. A difference equal to one amount usually means a missing line; twice an amount means a flipped sign.
