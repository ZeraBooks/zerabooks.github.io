README

Statement workpaper layouts

An accounting firm gets the most from converted bank statements when every file comes out in the column order and headings its own workpapers or import template expect, and every statement is checked against its printed balances first. This repo has a layout spec form, column mappings and a script that rearranges a converted statement and proves nothing was lost.

Files

File What it is
converted-statement.csv A fictional September 2026 checking statement after conversion: opening balance row, seven lines, debit, credit and running balance.
layout-spec-template.csv A form for writing down your firm's template: column order, heading, content, format and an example for each column.
mappings/signed-amount-workpaper.csv A mapping to a workpaper layout with client name, one signed Amount column, US dates and an empty tickmark column.
mappings/deposits-and-withdrawals.csv A mapping to a layout with separate Withdrawals and Deposits columns and day-first dates.
remap_columns.py Rearranges a converted statement with a mapping, then checks the row count, money in and out, opening plus activity against the last balance, and every running balance. Python 3, standard library only.
samples/ The two outputs the script makes from the sample statement.
sample-statements-checklist.md Which client statements to use when testing a converter, and what to check in every converted file.

How to use it

  1. Fill in layout-spec-template.csv from the template your team pastes statement data into.

  2. Copy one of the files in mappings/ and change it to match. Each row is one output column: its heading, the source column and a transform (copy, signed, date:FORMAT or const:VALUE).

  3. Run it on a converted statement:

    python3 remap_columns.py mappings/signed-amount-workpaper.csv converted-statement.csv workpaper.csv

  4. Read the last line. OK means the output has every line and the balances tie. CHECK FAILED names the line where the running balance breaks.

FAQ

Why check the running balance on every line, not just the closing balance?

A closing balance can tie while two errors cancel out. Checking each line against the one before finds where the first break is, so someone looks at one line instead of the whole statement.

Should amounts be one signed column or two?

Whatever your template expects. Import templates often want one signed Amount; audit workpapers often keep deposits and withdrawals apart. Both mappings are here.

Does a converter replace reviewing the statement?

No. It moves the review to the exceptions: statements that don't tie and lines that look wrong. Someone still reads those.
